# Content-Security-Policy Analyzer

A dependency-free Python utility for **passive Content-Security-Policy (CSP) review**.

The tool fetches a URL, reads its `Content-Security-Policy` response header, parses the directives, and reports common policy weaknesses.

It does not attempt to bypass CSP, execute injected content, or access protected cross-origin data.

## Features

- CSP header retrieval
- Directive-aware parsing
- Detection of `unsafe-inline`
- Detection of `unsafe-eval`
- Detection of wildcard `*` sources
- Informational review of nonce/hash-based script policies
- `object-src` hardening check
- `base-uri` hardening check
- Handling of HTTP error responses
- Redirect/final-URL reporting
- Human-readable output
- JSON output
- Configurable timeout
- Optional TLS verification bypass for authorized labs
- CI-friendly exit codes
- Unit tests
- GitHub Actions CI
- Standard-library-only

## Requirements

- Python 3.10+
- No third-party runtime dependencies

## Usage

Basic:

```bash
python3 csp_analyzer.py --url https://example.com
```

JSON:

```bash
python3 csp_analyzer.py \
  --url https://example.com \
  --format json
```

Custom timeout:

```bash
python3 csp_analyzer.py \
  --url https://example.com \
  --timeout 20
```

Authorized local/lab endpoint with certificate verification disabled:

```bash
python3 csp_analyzer.py \
  --url https://localhost:8443 \
  --insecure
```

## Example

Given:

```text
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'unsafe-inline' 'unsafe-eval' https://cdn.example;
  object-src 'none'
```

The analyzer can report:

```text
[MEDIUM] script-src: 'unsafe-inline' weakens CSP restrictions for this directive.
[MEDIUM] script-src: 'unsafe-eval' permits string-to-code evaluation patterns.
```

## Findings explained

### `unsafe-inline`

`'unsafe-inline'` weakens CSP restrictions for inline scripts or styles depending on the directive.

For script authorization, nonce- or hash-based policies are generally preferable where practical.

### `unsafe-eval`

`'unsafe-eval'` permits JavaScript evaluation patterns that CSP would otherwise restrict.

It should generally be removed unless the application has a documented compatibility requirement.

### Wildcard source

A source such as:

```text
script-src *
```

allows resources from arbitrary origins for that directive.

The severity depends on the directive. The analyzer intentionally does not treat every wildcard as automatically critical.

### Missing `object-src`

When legacy plugin content is unnecessary, a policy such as:

```text
object-src 'none'
```

can provide an additional hardening layer.

### Missing `base-uri`

If an application does not need arbitrary `<base>` elements, consider restricting the directive, commonly with:

```text
base-uri 'self'
```

or:

```text
base-uri 'none'
```

depending on application requirements.

### Script nonces/hashes

The tool reports an informational finding when `script-src` contains neither:

- a nonce
- a hash
- `'strict-dynamic'`

This is **not automatically a vulnerability**. Traditional source allowlists can be legitimate depending on the application's architecture.

## Important limitations

CSP analysis is contextual.

This tool does not:

- Prove exploitability
- Execute browser JavaScript
- Test DOM behavior
- Validate CSP in every browser
- Inspect dynamically generated policies
- Test authenticated application states
- Determine whether every listed origin is trustworthy
- Validate application-specific CSP requirements
- Replace browser-based security testing

A CSP that looks permissive in isolation may be intentional, while a seemingly strict policy may still be ineffective because of application behavior.

## Response policy vs. report-only policy

This utility reads:

```text
Content-Security-Policy
```

It does not treat:

```text
Content-Security-Policy-Report-Only
```

as an enforced policy.

A report-only policy is useful for testing and deployment preparation, but it does not enforce browser restrictions.

## Exit codes

| Code | Meaning |
|---:|---|
| `0` | No HIGH/MEDIUM finding identified |
| `1` | HIGH/MEDIUM security-review finding identified |
| `2` | Request or input error |

## Privacy

The tool does not submit credentials or attempt authenticated access.

JSON output includes the requested/final URL and the CSP header. Review output before sharing it publicly because URLs can contain sensitive paths or query parameters.
